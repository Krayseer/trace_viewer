# Как строится маршрут заказа

Документ описывает текущее сопоставление записей из выгрузок. Совпадение ключей и дат даёт кандидата на связь. Для подтверждения движения смеси, вагонетки или готовой партии нужна запись о переходе с идентификатором, который связывает обе стороны. Порядок чтения исходных книг и точные адреса записей описаны в [схеме XLS](xls.md).

## Заказ, ключ и версия шихты

| Термин | Смысл в приложении |
| --- | --- |
| Заказ | Строка книги «Заказы», адресуемая по месяцу листа и номеру строки XLS. Сквозного номера заказа в книге нет. |
| Марка массы (`mass`) | Код массы из заказа, каталога шихты и дозирования. По нему получаем версии для заказа. |
| Марка сырца (`raw`) | Код сырца из заказа. Он ограничивает поиск прессовки, садки и входов в печь. |
| Марка изделия (`product`) | Код готового изделия. По нему ищем дополнительные операции и сдачу. |
| Ключ шихты (`RecipeKey`) | Код распоряжения (`order_code`), номер шихты (`number`) и дополнительная марка (`mark`). Код распоряжения берётся из записей шихты и этапов. |
| Версия шихты | Компоненты из одного месячного каталога, у которых одинаковы марка массы, код распоряжения, номер шихты и даты начала и окончания действия. Дополнительные марки собираются из строк компонентов версии. |

Для заказа используется каталог месяца его листа. В список включаются версии с той же маркой массы. Сначала учитывается совпадение дополнительной марки, затем пересечение периода поиска со сроком действия версии, затем номер шихты и код распоряжения. Границы обоих интервалов включены.

В режиме `auto` выбирается единственная версия, у которой совпадает дополнительная марка и срок действия пересекается с периодом поиска. При нуле или нескольких таких версиях действует `all`. Явный идентификатор версии принимается, если версия есть в списке для этой марки массы. Для поиска по конкретной дате проверяется срок действия на эту дату. При разрешении ключа строки прессовки используется каталог её фактического месячного листа.

Совпадение с каталогом позволяет объяснить подбор. Технологическую допустимость версии для заказа подтверждает отдельное технологическое правило. [Реализация каталога](../server/recipes.py) · [Выбор версии для маршрута](../server/trace.py#L95)

## Этапы и интервалы

Период по умолчанию — календарный месяц листа заказа. Точный поиск дозирования, прессовки, садки и входа в печь учитывает обе границы периода и выбранную смену. Без фильтра смены подходящие записи берутся из всех смен.

| Этап | Отбор и сверка |
| --- | --- |
| Подача порошков | Код материала сверяется с компонентами выбранных версий, действующих в периоде. Поиск включает день перед началом периода. Подача даёт контекст по материалу. Связь с замесом в записях отсутствует. |
| Дозирование | Проверяются марка массы, ключ шихты и действие выбранной версии на дату записи. При пустом точном поиске отдельно показываются подходящие записи до семи дней с каждой стороны периода, для всех смен. Каждая строка дозирования описывает компонент. |
| Прессовка | Сначала проверяется сырец заказа, затем ключ шихты. Совпадением считается единственная действующая на дату записи версия, входящая в выбранные активные версии. Близкие записи с отсутствующим или расходящимся ключом могут отображаться с предупреждением. |
| Садка и печи | Отбор идёт по сырцу заказа и ключам показанных прессовок, с датой садки или входа в печь не раньше подходящей прессовки. Совпадение ключа, даты и смены между соседними этапами используется для пояснения списка кандидатов. Дата выхода из печи хранится отдельно. |
| Дополнительные операции и сдача | Поиск по коду изделия идёт от начала периода до четырёх дней после его конца или последнего показанного выхода из печи, если тот позже. Верхняя граница включена. Дата раньше всех показанных выходов отмечается как расхождение. У дополнительных операций сверяется ключ шихты с прессовками, у сдачи — дополнительная марка с заказом. |

При сверке дозирования с прессовкой совпадение даты, смены и полного ключа даёт признак `matching_slot` у перехода. Разный код распоряжения при совпадении даты, смены, номера шихты и дополнительной марки может дать расхождение. Несколько прессовок с одинаковыми датой, сменой, ключом и кодом пресса дают неоднозначность при переходе к садке.

Нормы прессовки, групповые проценты и простои дают справочный контекст. Нормы отбираются по сырцу с учётом прессов из найденных строк. Проценты сверяются по кодам групп сырца и изделия. Простои сверяются по коду оборудования и пересечению дат с периодом поиска. [Правила этапов и переходов](../server/trace.py)

## Покрытие и порядок заказов

Покрытие рассчитывается по семи производственным этапам от подачи до сдачи для всех заказов листа с заполненной маркой массы. Для расчёта используются календарный месяц, поиск без ограничения смены и режим `auto`. Этап засчитывается, если по его правилам найдена хотя бы одна строка без статуса расхождения. Для подачи, дополнительных операций и сдачи действуют расширенные интервалы из таблицы выше. Соседнее дозирование помечается `outside_period` и в покрытие не входит. Расхождения считаются по числу разных этапов, на которых есть строка с расхождением или расхождение на входящем переходе. Неоднозначности считаются по переходам.

Заказы сортируются по убыванию покрытия, затем по возрастанию числа этапов с расхождениями и числа неоднозначных переходов, затем по наличию совпадения дозирования и прессовки по дате, смене и ключу. При равенстве используется номер строки XLS. «Лучшие маршруты» оставляет заказы, у которых засчитаны подача, дозирование и прессовка. «Без расхождений» дополнительно требует ноль этапов с расхождениями.
