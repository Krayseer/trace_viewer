# Выгрузки XLS и адреса источников

По умолчанию приложение читает книги из каталога `Данные` в корне практикума. Путь можно задать через `--data`. Для каждой книги адаптер сначала ищет файл с номером перед названием, затем файл без номера. Число в колонке «Файл» соответствует значению `Book` и параметру `file` в API. Названия файлов и сопоставление столбцов с полями задают [модели записей](../server/records.py) и [адаптер XLS](../server/data.py). Ниже перечислены поля, которые важны для понимания маршрута и исходных строк.

| Файл | Книга | Основные поля |
| --- | --- | --- |
| 1 | Заказы | Коды массы, сырца и изделия, коды групп, дополнительная марка, основной и дополнительный объёмы заказа в тоннах. |
| 2 | Шихта | Код массы, код распоряжения, номер шихты, дополнительная марка, даты начала и окончания действия, код компонента и его норма в процентах. |
| 3 | Подача порошков | Дата, код материала `nMaterialId`, вес в тоннах. |
| 4 | Линии дозирования | Дата, смена, марка массы, поля ключа шихты, код компонента, годное и брак в тоннах. |
| 5 | Нормы прессовки | Код сырца, коды прессов, норма в штуках. |
| 6 | Прессовка | Дата, смена, код пресса, код сырца, поля ключа шихты. Годное и брак представлены отдельными полями в штуках и тоннах. |
| 7 | Садка | Дата, смена, вагонетка, код сырца, поля ключа шихты, количество в штуках и тоннах. |
| 8 | Печи | Код печи, дата и смена входа, отдельная дата выхода, код сырца, поля ключа шихты, количество в штуках и тоннах. |
| 9 | Доп операции | Дата, операция, код изделия, поля ключа шихты, годное и брак в штуках и тоннах. |
| 10 | Сдача | Дата, партия сдачи, код изделия, дополнительная марка, количество в штуках и тоннах. |
| 11 | Проценты | Коды групп сырца и изделия, групповые показатели брака и потерь в процентах. |
| 12 | Простои | Код оборудования, даты и время начала и окончания, часы простоя. |

Заголовки и единицы в таблице сверены с листами «март 2022». При добавлении поля проверь заголовок, тип и значения в затронутых книгах и листах. Позиции столбцов смотри в `server/data.py`, в том числе в `production_record()` и таблицах дат, ключей и отображаемых колонок. Границы поиска и способы сопоставления описаны в [правилах трассировки](traceability.md).

## Лист, строка и дата

- Месяц `YYYY-MM` получается из имени листа вида «март 2022». При разборе учитываются регистр, пробелы и вариант «аперль». Фактическое имя листа сохраняется. Месяцы для списка заказов берутся из книги «Заказы».
- Строка заголовка имеет номер 1. Первая строка данных имеет номер 2. Полностью пустые строки пропускаются, исходные номера остальных строк сохраняются. Строка с незаполненной обязательной датой этапа остаётся доступна по исходному адресу при наличии других значений, хотя в датированную выборку этапа она не попадает.
- Для сопоставления строковые значения очищаются от пробелов по краям, числа с нулевой дробной частью преобразуются в `int`. Исходные ячейки хранятся отдельно. Пустые значения сохраняются, а отсутствие даты представляется в предметной записи как `None`.
- Даты читаются из положительных чисел в известных столбцах с учётом системы дат книги. В API просмотр дат обычно использует ISO-дату, а для начала и окончания простоя сохраняет время с точностью до минут. В «Печах» важно сохранять оба поля: вход задаёт дату отбора, выход используется и показывается как отдельная дата.
- Адрес записи включает книгу, месяц и фактическое имя её листа, а также номер строки XLS. Датированный индекс охватывает все прочитанные месяцы. При пересечении границы месяца запись маршрута может прийти с листа, отличного от листа заказа.

`GET /api/source` принимает `file`, `month` и `row` и возвращает имя реально открытого файла, название листа, номер строки и её поля. Для запроса бери месяц из ссылки на запись. Случай с апрельской строкой мартовского заказа приведён в [регрессионных проверках](regression.md#проверки-api).
