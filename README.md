# Маршрут заказа по выгрузкам

Локальное приложение на Python читает 12 исходных книг `Данные/*.xls`. В настольном браузере слева открыт список заказов, справа — маршрут, шихта и справочные таблицы выбранного заказа.

## Запуск

Из корня проекта с существующим окружением:

```sh
implementation/.venv/bin/python -m implementation.trace_viewer.server --open
```

Из отдельного клона этого репозитория укажите папку с исходными выгрузками:

```powershell
python -m pip install xlrd numpy scipy "highspy==1.12.0"
python -m server --data "../project practicum/Данные" --open
```

Адрес приложения — [http://127.0.0.1:8766/](http://127.0.0.1:8766/). Порт можно изменить через `--port`, папку данных через `--data`. Сервер слушает только `127.0.0.1`. Python 3.10+ и `xlrd` нужны для чтения `.xls`, NumPy и SciPy нужны для планирования. Для остановки нажмите `Ctrl+C` в терминале.

## Стенд на GitHub Pages

[Открыть стенд](https://krayseer.github.io/trace_viewer/). Workflow **Deploy GitHub Pages** собирает и публикует сайт при пуше в `master`. В разделе **Actions** его можно запустить вручную через **Run workflow**. В настройках репозитория в разделе **Pages** источником публикации служит **GitHub Actions**.

Для просмотра данных введите ключ доступа, полученный от владельца проекта. Ключ сохраняется на время сессии вкладки, поэтому после обновления страницы выгрузки открываются автоматически. Браузер расшифровывает архив из 12 XLS и рассчитывает маршруты в отдельном потоке. Передавайте ключ только участникам с доступом к выгрузкам.

Ссылка вида `https://krayseer.github.io/trace_viewer/#key=ВАШ_КЛЮЧ` открывает выгрузки автоматически. Браузер убирает ключ из адресной строки после считывания. Ссылка даёт такой же доступ, как сам ключ.

Для обновления выгрузок из корня этого репозитория пересоберите зашифрованный архив. Для этой команды нужны `xlrd`, `cryptography` и приватный файл с ключом. Закоммитьте `pages/workbooks.zip.enc` и отправьте изменения в `master`.

```sh
python -m server.seal_workbooks --data ../../Данные \
  --key-file /путь/к/ключу --output pages/workbooks.zip.enc
```

## Планирование

Откройте вкладку **Планирование** или добавьте `?view=planning` к адресу. Слева доступны список сценариев, загрузка полного JSON в формате примеров из `web/planning_examples` и пересчёт. Меняйте объёмы во вкладке **Заказы** и ограничения во вкладке **Лимиты**. После пересчёта **План** показывает назначения и независимую проверку, а **Расход** показывает остатки, загрузку, узкие места и изменённые лимиты. Вкладка **Источники** содержит допущения и происхождение исходных лимитов по компонентам.

На GitHub Pages синтетические примеры и загрузка собственного JSON доступны сразу. Мартовский и майский примеры из выгрузок открываются тем же ключом, что и XLS. Расчёт выполняется в браузере. При смене ключа или обновлении этих примеров пересоберите также `pages/planning_examples.zip.enc`:

```sh
python -m server.seal_workbooks --planning-examples ../planner/examples \
  --key-file /путь/к/ключу --output pages/planning_examples.zip.enc
```

## Сравнение алгоритмов

Откройте вкладку **Сравнение алгоритмов** или добавьте `?view=comparison` к адресу. В **Сохранённых запусках** доступны по три парных повтора для двух синтетических сценариев на 500 заказов. Таблица показывает цель, полный отклик, разрыв и подтверждение тёплого старта. На GitHub Pages эти результаты доступны без ключа.

Для **Нового расчёта** запустите локальный сервер с NumPy, SciPy и `highspy==1.12.0`. Чтобы открыть сравнение и учебное планирование без исходных XLS, выполните из клона:

```powershell
python -m server --synthetic-only --open
```

Выберите малый пример, учебный сценарий на 30 заказов, несовместный пример или загрузите полный JSON планировщика. Методы выполняются последовательно на одном входе. Бюджет задаётся отдельно на каждый метод. Время нового расчёта измеряется от начала метода до проверки плана и включает построение модели и подготовку тёплого старта. Разворачиваемые блоки под таблицей показывают назначения и баланс компонентов для каждого найденного плана.

Для демонстрации выберите учебный сценарий на 30 заказов. Ожидаемые условные цели — 302,18 у быстрого метода и 303,97 у двух режимов HiGHS. Затем выберите несовместный пример, чтобы показать различие между отсутствием плана у эвристики, доказанной несовместностью у холодного MILP и отсутствием начального плана для тёплого запуска.

## Как читать

- В левой панели **Заказы** выберите месячный лист и найдите заказ по номеру строки, наименованию или коду. В списке перед наименованием изделия указан номер строки XLS. Заказы открываются за весь месяц своего листа. Версию шихты и смену можно изменить над маршрутом.
- **Лучшие маршруты** оставляет заказы с записями подачи, дозирования и прессовки без расхождений в этих записях. Покрытие считается по семи этапам для всего листа, обеих смен и автоматического выбора шихты. Этап входит в покрытие, если по правилам поиска для него есть хотя бы одна строка без расхождения. Соседнее дозирование вне периода в покрытие не входит. Список упорядочен по покрытию, количеству этапов с расхождениями, неоднозначности и совпадению шихты, даты и смены между дозированием и прессовкой. **Без расхождений** оставляет заказы с нулём отмеченных расхождений. Оценка описывает найденные записи и кандидатов на переходы.
- В шапке заказа видны наименование и исходные коды изделия, марки сырца и марки массы, доп. марка и объём. Кнопка **Строка XLS** показывает номер строки в книге заказов и открывает её. Ненулевой объём из поля «Доп. заказ, тн.» показан отдельным значением.
- Потяните правую границу панели **Заказы**, чтобы изменить ширину. Когда разделитель в фокусе, клавиши ← и → меняют ширину, а Home и End устанавливают её минимум и максимум. Кнопка рядом с заголовком сворачивает и раскрывает панель.
- Выберите этап в полосе маршрута над таблицей. У входящего перехода видны расхождения, недостающие данные и ссылки на исходные строки. В «Подаче порошков» плашка над таблицей поясняет переход к дозированию. Кнопки **?** открывают правила подбора. Имя книги и лист видны при открытии исходной строки. Справочник норм доступен в разделе прессовки.
- Номер в полосе маршрута выбирает переход, а такой же номер в заголовке таблицы отмечает поля проверки. В подсказке видны обе книги и правило сравнения. Кнопка в баннере открывает вторую сторону с теми же метками. Красный отмечает расхождение перехода или конкретного поля, жёлтый — неоднозначность, зелёный — совпадение ключа, даты и смены у дозирования и прессовки, синий — кандидатскую связь. Совпадение полей помогает искать кандидатов на передачу партии. Метки **i** отмечают поля справочной сверки.
- Нажмите на заголовок столбца, чтобы отсортировать таблицу. Повторное нажатие меняет направление. Сортировка охватывает всю выборку, включая строки за кнопкой **Показать ещё**. Пустые значения отображаются в конце.
- В таблице **Печи** даты входа и выхода показываются рядом. Вкладка **Шихта** показывает состав и срок действия версий. Во вкладке **Проценты и простои** видны начало и окончание каждого записанного простоя.
- **Строка 145 листа «март 2022»**. На переходе к прессовке показано расхождение за 28 марта: `3181/59` в дозировании, строка 3637, и `3171/59` в прессовке, строка 655. В справочнике им соответствуют марки массы `153356` и `153357`. Во второй смене есть две строки прессовки с одинаковыми признаками подбора и 120 и 370 годными штуками.
- **Строка 184 листа «март 2022»**. В таблицах видно дозирование от 3 марта, строка 332, и прессовку от 1 марта, строка 2.
- **Строка 148 листа «март 2022»**, этап **Печи**. В строке 197 вход указан 4 марта, выход 5 марта 2022 года.
- Список версий объединяет записи каталога с той же маркой массы и показывает совпадение доп. марки и срок действия. При единственном действующем совпадении с доп. маркой эта версия открывается первой. Можно выбрать другую версию или все сразу. Допустимость применения по заказу требует технологического правила.
- Даты и смена ограничивают дозирование, прессовку, садку и вход в печь. Для подачи порошков включён один предшествующий день. При пустом точном поиске дозирования совпадения в пределах семи соседних дней показаны отдельно для всех смен. Дополнительные операции и сдача ищутся по изделию до четырёх дней после конца периода или последнего показанного выхода из печи, если он позже. Это границы поиска кандидатов.
- У исходных записей сохраняются фактическое название листа и номер строки XLS, включая строку заголовка. Совпадение полей рецептуры связывает запись со справочником. Для подтверждения движения смеси, вагонетки и готовой партии нужен журнал переходов.

## Проверка

Для регрессионной проверки используйте строки 145, 148 и 184 листа «март 2022» в книге заказов. У 145 проверьте предупреждение на переходе к прессовке и открытие строк XLS, у 148 обе даты строки 197 в таблице **Печи**, у 184 даты дозирования и прессовки.
